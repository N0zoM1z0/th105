## Correcting the old ownership inference

CEffectSprite because421FF0 installs its vptr and calls reset435110, whose
stores extend through128. That did not establish that the stores belonged to
the polymorphic sprite itself. A constructor can initialize a sprite member
and then reset the containing nonpolymorphic object's subsequent fields.

## Background initialization

Both handle and sprite vectors use assign, not resize. The sprite fill value
is an expression-scoped CEffectSprite temporary, so its cleanup state ends
before the texture loop. Native loops over30 tiles, formats the BG path,
loads and stores each handle, and applies256x256 texture regions for nonzero
handles. Column then row calculations, (i%6)*256 and (i/6)*256, reproduce the
observed shared quotient and row spill. The reverse local declaration order
was514/512; signed and unsigned grid expressions alone were byte-neutral.

The complete512-byte match resolves the historical temporary-type/frame stop.
It was not a demonstrated LTCG dead-tail phenomenon: the old element type and
resize operation were wrong. BG02/BG04 constructor hypotheses require the same
new ownership evidence to be applied separately; they receive no credit here.
