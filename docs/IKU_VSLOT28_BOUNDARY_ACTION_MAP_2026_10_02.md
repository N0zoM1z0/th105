## First action family's x87 dataflow

**Observed target instructions:** the compressed low table selects actions 0–3 at `620B22`, `620BF7`, `620CC8` and `620CE3`. Each starts with the exact-backed landing helper at `473DD0`. Actions 0/2 share the damping block beginning `620B60`; actions 1/3 have separate but instruction-equivalent damping blocks beginning `620C13`/`620CFF`. The compared field is a four-byte float at receiver `+0xF4`, while the branch gate is a byte at `+0x47E`. The arithmetic constant at `6CD138` is the exact eight-byte double `0.5`. Positive values subtract it; negative values add it. Each path stores the arithmetic result to a four-byte stack slot at `[esp+0x10]`, reloads it, stores it to `+0xF4` with nonpopping `FST`, then compares the still-live rounded float against x87 zero. A crossing invokes the exact-backed zero-velocity helper at `45AF40` and clears `+0x47E`. The status-word tests are `AH & 0x05` and `AH & 0x41`; they retain unordered-float behavior that an algebraic rewrite may change. Action 0's zero-value precheck additionally clears `+0x47E` at `620B38`.

The control-flow owner is not a simple consecutive case slice: action 2 at `620CD6` jumps back into action 0's shared zero-velocity/float tail, and action 0 at `620BAD`/`620BD4` branches to the remote shared return at `62EAC9`/`62EACB`. Actions 1/3 call the exact-backed frame helper at `4351C0` and, only after its nonzero byte result and a zero word at `+0x140`, call virtual slot `+0x08` with argument 2/0 respectively. The field meanings, source expression spelling, exception behavior and original compiler ownership remain unproven. These instructions support a future natural-source trial with explicit single-precision storage and live-value comparisons; they do not prove byte equality or an assembly requirement.
