## Ownership and parsing policy

CScript::load owns FileBufferContext. Failure returns without clearing pending
commands. Success clears the pending commands, tokenizes with CR/LF, skips
lines whose first byte is '#', dispatches the remaining lines, and resets the
current iterator to pending.begin(). The second public stack argument remains
unused, as observed in the native RET 8 interface.

The ordinary line parser is present as real caller context but remains
unaccepted: source 405 bytes versus native 399. Its shared map/string/deque
helper context and frame differ. CSV load and CSV parsing also remain
unaccepted. No partial-byte credit is assigned to these functions.

## Source-owned CR/LF object

scripts/linked_literals.py verifies the genuine compiler byte-string object
??_C@_02PCIJFNDE@?$AN?6?$AA@ against native 6D69B0. All three bytes, 0D 0A 00,
must match. The CIL map owner must be unique; both sections must be read-only
and non-executable. The compiler-encoded extent and complete byte identity
are checked. Explicit read offsets 0 and 2 must already exist in the target
data ledger. No target addend allowlist was widened.

Only bounded MOV/MOVZX/MOVSX register reads are admitted by this contract.
Writes, address escape, unlisted interior offsets and overrun fail. Actual
HIGHLOW relocation coverage remains mandatory. This recovers the real
source literal rather than splitting it into artificial globals.
